# 发薪存证中心设计

日期：2026-08-20  
状态：已确认，等待实现计划

## 目标与范围

将现有仅展示原始存证事件流水的“发薪存证”页面扩展为两级管理界面：先按员工查看存证，再进入单个员工的发薪记录，按月份和发送/查看/确认状态筛选，并导出 Excel 存证明细。

本次不实现 PDF、不采集个人签名、不新增确认人字段、不接入 Router/Redux/React Query，也不改变工资发送、撤回、确认和归档业务规则。

员工在职状态按当前钉钉通讯录判断：通讯录中存在该 `userId` 为在职，不存在为已离职。该状态是查询时的实时分类，不写入工资数据库。

访问范围为主管理员和子管理员：主管理员可访问全部批次（含历史归档），子管理员只能访问现有 `access.batchIds` 中且未归档的批次。未授权批次不得进入员工计数、详情或导出结果。

## 方案选择

采用后端专用存证服务、前端两级页面、服务端 Excel 导出的组合：

1. 不让浏览器拼装原始存证、批次和工资明细，避免敏感工资数据过度下发并保持权限判断在服务端。
2. 不把存证聚合继续塞入 `ReportService`，避免报表汇总、存证查询和文件导出互相耦合。
3. 复用 API 已有 `xlsx` 运行时依赖，不新增依赖。

## 后端接口与数据流

新增存证服务（放在现有 reports 模块内），由路由负责会话身份和 Zod 参数解析，服务负责批次权限、员工聚合、状态计算和导出数据组装。

### 员工列表

`GET /v1/payment-evidence/employees`

查询参数：

- `employmentStatus=active|departed`，可选；
- `query`，可选，服务端对姓名、工号、职位做不区分大小写的包含匹配。

返回员工摘要数组，每个员工包含：

- `employeeUserId`、`employeeName`、`employeeNo`、`department`、`position`；
- `employmentStatus`；
- `evidenceCount`（可见的非草稿工资条条数，而不是事件条数）；
- `latestEvidenceAt`。

列表响应不得包含 `fields`、工资金额、银行卡号或其他工资敏感值。员工列表只读取批次摘要和批次内员工元数据，不调用 `listBatches()`，也不为未授权批次调用 `getBatch()`。

### 员工详情

`GET /v1/payment-evidence/employees/:employeeUserId`

查询参数：

- `fromMonth`、`toMonth`，格式 `YYYY-MM`，按工资批次的 `payrollMonth` 闭区间筛选；
- `sendStatus=not_sent|sent|failed|withdrawn`；
- `viewStatus=not_viewed|viewed`；
- `confirmStatus=not_confirmed|confirmed`。

服务先取得允许批次摘要，再仅对筛选命中的允许批次调用 `getBatch()`。详情行包含：

- `batchId`、`itemId`、工资月份、工资条标题、批次状态；
- 员工身份快照；
- 服务端计算的发送状态、发送时间、查看状态、查看时间、确认状态、确认时间、确认人；
- 该管理员有权查看的工资字段和值，用于详情展示和字段选项生成。

发送状态以该员工在批次中的最新投递记录为准：无投递为 `not_sent`，最新记录为 `delivered`/`failed`/`withdrawn` 时分别映射为 `sent`/`failed`/`withdrawn`。确认人沿用现有模型，取确认该工资条的员工 `employeeUserId`；没有确认记录时为 `null`。不新增签名或确认人存储字段。

详情只包含有存证价值的非草稿批次中的该员工工资条。子管理员对归档批次沿用现有工资管理边界，不显示归档数据。

### Excel 导出

`POST /v1/payment-evidence/export.xlsx`

请求体复用员工、月份和三类状态筛选，并带 `fields: string[]`。服务端重新计算允许批次和实际字段集合：未知字段、未在筛选结果中出现的字段或越权批次都不能导出。

固定列始终存在且不可取消：

`员工姓名`、`工号`、`职位`、`工资月份`、`工资条标题`、`发送状态`、`查看状态`、`确认状态`、`确认时间`、`确认人`。

用户选择的工资字段追加在固定列之后，默认全选。响应为 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` 文件，并通过已有 `xlsx` 包生成。导出审计只记录筛选条件是否存在、字段数量和行数，不记录工资值。

### Store 窄查询

在 `SalaryStore` 和两种实现中增加批次员工元数据查询（名称、工号、部门、职位、员工 ID、查看/确认时间），不返回 `fields`，也不触发 AES 解密。该接口服务员工列表聚合和权限边界测试；详情/导出仍使用现有 `getBatch()` 读取已筛选且授权的批次。

原始 `GET /v1/payment-evidence` 事件接口继续保留，不改成多态响应；页面 smoke test 将改为 mock 新的员工列表/详情接口，原始事件接口另保留 API 兼容回归测试。

## 前端交互

继续使用现有 `EvidenceCenter` 入口和页面组合，不引入路由基础设施。

### 员工列表

- 在职/已离职 tab；
- 姓名/工号/职位搜索框，按提交或短暂防抖请求服务端；
- 员工表格显示身份、存证数量、最近时间和“查看发薪存证”；
- 首次加载、空结果、错误都保留明确反馈。

### 员工详情

- 返回列表和员工信息头部；
- 发薪月份起止选择；
- 筛选弹窗包含发送、查看、确认三组状态；
- 记录表显示工资月份、标题、状态、确认时间、确认人及工资明细；
- “导出 Excel”打开字段选择弹窗，固定列说明和工资字段复选框清晰区分；
- 使用 `fetch` 接收 Blob 并触发下载，失败时显示服务端错误。

不改变现有发薪管理、员工工资条、撤回提示、颜色、移动端和打印行为。

## 安全与错误处理

- 未登录返回现有 401；员工身份访问存证中心拒绝；其他无权限身份沿用现有错误映射。
- 子管理员批次权限由服务端 `Access` 重新计算，前端传入的员工 ID、批次 ID、字段名和筛选条件都不作为授权依据。
- 列表不解密工资字段；详情/导出只解密当前允许批次；未授权批次不通过错误信息或计数泄露存在性。
- 不在日志、审计 metadata 或错误文本中记录工资金额、字段值、密钥或身份证/银行卡信息。
- 目录查询失败、批次读取失败和导出失败都向调用方返回错误，不静默降级或伪造空结果。

- 员工列表不调用 `listBatches()`，且未授权批次不调用 `getBatch()`；

## 非目标

- 不实现 PDF、签名采集、温馨提示导出；
- 不修改发送、撤回、重发、确认或归档逻辑；
- 不新增数据库、ORM、缓存、消息队列、Router、状态管理库或 PDF 库；
- 不做与存证功能无关的 CSS/React 拆分或部署操作。
